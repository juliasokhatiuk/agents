# Що таке RAG і які є підходи до retrieval?

## Огляд
Retrieval-Augmented Generation (RAG) — це підхід, який комбінує механізм пошуку релевантних документів із генеративною моделлю (LLM). Замість того, щоб повністю покладатися на параметричну пам'ять моделі (те, що "знає" модель після навчання), RAG витягує зовнішні фрагменти тексту з індексу/корпусу і використовує їх як контекст для генерації відповіді. Це дозволяє отримувати свіжу, доменно-специфічну та більш достовірну інформацію без перетраєння великої моделі.

## Коротка схема pipeline RAG
1. Інгестія / розбиття документів (chunking) та індексація (створення embeddings або інвертованого індексу).
2. Запит користувача -> компонент retrieval (отримує топ-k фрагментів).
3. (Опціонально) Фільтрація / reranking / multimodal alignment.
4. Генератор (LLM) отримує запит + вибрані фрагменти і формує відповідь.

## Основні підходи до retrieval
1. Лексичні (sparse) retrievers
   - Приклад: BM25 (класичний інвертований індекс). Шукає на основі ключових слів, добре працює для точних ідентифікаторів, технічних термінів, і там, де важлива точна відповідність.
   - SPLADE: більш сучасний sparse-підхід, який перекладає документи і запити у розріджене представлення з вагами.
   - Переваги: швидко, інтерпретується, не вимагає тренування embeddings; Мінуси: погано ловить синонімію та семантичні відношення.

2. Семантичні (dense) retrievers
   - Приклад: DPR, Sentence-BERT, колбек (bi-encoder) — запити та документи кодуються в embeddings; пошук по векторному індексу (ANN/FAISS, ScaNN, Milvus).
   - Late-interaction: ColBERT — зберігає токенні представлення й використовує ефективний ранжир для кращої точності.
   - Переваги: знаходять семантично релевантні фрагменти; Минуси: дорожчі в індексації, залежать від якості embeddings; вразливі до доменної невідповідності.

3. Гібридні системи
   - Поєднання sparse + dense: виконують BM25 та vector search паралельно, потім зливають результати (fusion) або використовують BM25 для пріоритизації.
   - Часто дає кращий recall, особливо на технічних або зшитих даних.

4. Багатоступеневий retrieval (multistage)
   - 1-й етап: швидкий, високорекол-набір (BM25 або ANN) для отримання великого пулу (наприклад top-100).
   - 2-й етап: більш точне reranking (cross-encoder neural re-ranker або instruction-following re-ranker) для вибору top-k, які підуть до генератора.
   - Дозволяє зменшити затрати часу/пам'яті та підвищити якість фінального набору.

5. Реранкінг (re-ranking)
   - Cross-encoder (BERT-подібні моделі), які оцінюють пару (запит, документ) з високою точністю, але дорожчі.
   - Neural re-rankers, learning-to-rank парадигми.
   - Instruction-based rerankers: LLM або спеціальні моделі можуть оценити відповідність за складними критеріями (фактичність, стиль).

6. Тренування ретривера
   - Самонавчання / weak supervision (LLM weak labeling), distillation.
   - Супервізоване тренування (DPR): позитивні/негативні приклади, contrastive loss.
   - Pretraining retrieval tasks: Inverse Cloze Task (ICT) — тренує модель відновлювати фрагмент по контексту; допомагає ініціалізувати ретривер.
   - Fine-tuning через сигнали від генератора (minimize KL між retriever і генераторним розподілом) — alignment retriever-generator.

7. Новіші ідейні підходи
   - HyDE (Hypothetical Document Embeddings): генерація гіпотетичного документу відповіддю LLM, потім вбудовування його для покращення retrieval.
   - Agentic RAG / multi-hop RAG: рекурсивний/багатокроковий пошук для складних запитів, коли потрібні декілька документів або reasoning steps.
   - RETRO-like підходи: інтегрування retrieved chunks прямо в архітектуру моделі (chunked cross-attention) замість прикрадання як простого prompt.

## Інженерні моменти та метрики
- Метрики: Recall@k (важлива для retrieval), MRR, Precision@k, а також якість фінальних відповідей (factuality, ROUGE/EM для QA).
- Гранулярність: вибір chunk-довжини (параграфи vs sentences vs whole docs) впливає на recall і concise-сть контексту.
- Сторонні компоненти: metadata filtering, time-based filtering (для оновлюваної інформації), multimodal embeddings (для зображень/таблиць).
- Виклики: hallucinations (LLM ігнорує retrieved evidence або комбінує неправильно), latency (особливо з cross-encoders), якість індексації та drift домену.

## Коли що використовувати (практичні поради)
- Якщо дані мають точні коди і терміни (реєстри, продукти): BM25 або гібрид BM25+embeddings.
- Якщо потрібна семантична релевантність (FAQ, підтримка, general-domain QA): dense retriever (DPR/SBERT) + ANN.
- Для критичних по фактах застосунків: багатоступеневий pipeline + cross-encoder reranker + валідація фактів.
- Для масштабних корпусів: індексація embeddings у ANN (FAISS/Milvus) + metadata filtering для зниження шуму.

## Ключові висновки
- RAG дає змогу оновлювати знання LLM без перетренування: додає зовнішній релевантний контекст.
- Підходи до retrieval: від простих лексичних (BM25) до складних dense/late-interaction і гібридних систем; часто комбінують кілька методів у багатоступеневому pipeline.
- Тренування ретривера (ICT, supervised contrastive learning, weak supervision) і reranking істотно впливають на кінцеву якість.
- Вибір методу залежить від домену, вимог до latency, точності та наявності розмічених даних.
