# RAG (Retrieval‑Augmented Generation) — Огляд і підходи до retrieval

## Огляд
RAG (Retrieval‑Augmented Generation) — це підхід, який поєднує великий мовний (генеративний) модель із механізмом пошуку (retrieval) зовнішньої інформації. Замість покладатися лише на знання, закодовані в параметрах моделі, RAG підтягує релевантні документи/фрагменти з бази знань і використовує їх як контекст під час генерації відповіді. Це дає змогу отримувати більш фактичні, спеціалізовані та актуальні відповіді, а також надавати джерела (прозорість).

## Компоненти RAG
- Retriever (механізм пошуку): знаходить Top‑k релевантних фрагментів документів з індексу.
- Index / база знань: може бути повнотекстова (документи), розбита на пропозиції/параграфи, або векторна база (embedding index).
- Generator (семантично — seq2seq або великий трансформер): отримує промпт, який містить запит + витягнуті фрагменти, і генерує відповідь.

Типова pipeline: 1) отримаємо вхідний запит; 2) retriever повертає k фрагментів; 3) складання контексту (concatenate/condition); 4) генератор створює текст (з можливістю підвантаження різних фрагментів під час генерування).

## Основні підходи до retrieval (деталі і порівняння)
1. Sparse retrieval (класифічні IR)
   - Приклади: BM25, TF‑IDF.
   - Переваги: швидко, інтуїтивно, легко індексувати; добре працює при великому наборі текстів із правильними ключовими словами.
   - Недоліки: слабка семантична відповідність для перефразованих запитів.

2. Dense retrieval (нейронні embeddings)
   - Приклади: DPR (Dense Passage Retrieval), bi‑encoder архітектури.
   - Ідея: запит і документи кодуються в векторний простір; знаходять найближчі вектори (ANN пошук — FAISS, Annoy, ScaNN).
   - Переваги: краща семантична релевантність, працює при перефразуванні.
   - Недоліки: потребує тренування ембедінгів, дорожчий індекс; можливі колізії в семантиці.

3. Cross‑encoder reranking
   - Працює як другий етап: кандидати від bi‑encoder (dense/sparse) знову оцінюються моделлю cross‑encoder, яка разом обробляє пару (запит, документ) і дає точнішу оцінку релевантності.
   - Переваги: висока точність ранжування.
   - Недоліки: повільно та обчислювально дорого для великого числа кандидатів.

4. Гібридні підходи
   - Комбінація sparse + dense: використати BM25 для швидкої фільтрації + dense для семантики або навпаки.
   - Часто дає кращий компроміс швидкість/якість.

5. Granularity та стратегія retrieval
   - Рівні: документ, параграф, абзац, речення, чанки фіксованого розміру.
   - Впливає на обсяг контексту, шум і точність відповідей.

6. Частота та рівень застосування retrieved контенту
   - Per‑sequence (RAG‑Sequence): однаковий набір витягнутих фрагментів використовується для всього генерованого виходу.
   - Per‑token (RAG‑Token): генератор може умовлятися на різних фрагментах для кожного токена (дозволяє гнучкіше використовувати багато джерел). (Це формулювання описане в оригінальній статті Lewis et al.)

7. Тренування та покращення retriever'а
   - Pretraining for retrieval: Inverse Cloze Task (ICT) — модель навчається прогнозувати відсутній шматок документа з його контексту, що покращує здатність знаходити релевантні сегменти.
   - Supervised fine‑tuning: тренування на парі (запит, позитивний документ) із контрастивними негативними прикладами (contrastive learning).
   - Joint / end‑to‑end training: у RAG можна тонко налаштовувати retriever і generator разом (з урахуванням генераторної втрати), що вирівнює ранжування під генераторні цілі.
   - Reranking training: навчити cross‑encoder‑переранжувальник на людських мітках/перплексії генератора.
   - Retriever optimization via generator feedback: підходи, які вирівнюють ймовірність вибору документів retriever'ом із ймовірністю генератора (наприклад мінімізувати KL‑відстань між ними).

8. Індекси та пошук (“ANN”)
   - Для dense retrieval застосовують approximate nearest neighbor (ANN): FAISS, Annoy, HNSW, ScaNN.
   - Питання: trade‑off пам'ять/швидкість/точність; оновлення індексу (додавання нових документів).

9. Інші практичні аспекти
   - Фільтри, бустинг по метаданих, доступ до зовнішніх баз (SQL, KB), кешування запитів, дедублікація і скорочення здуття контексту (truncation).
   - Оцінювання: MRR, Recall@k, точність ранжування, а також людська оцінка якості згенерованих відповідей.

## Коротке порівняння (підсумок)
- BM25: швидко, простіше індексувати, гірше зі смисловими запитами.
- Dense (bi‑encoder/DPR): краща семантична релевантність, потребує тренування/ANN, добре для парафраз.
- Cross‑encoder reranker: найкраща точність ранжування, але дорого обчислювально — застосовується як другий шар після швидкого фільтра.
- Joint RAG training (Sequence vs Token): Token більш гнучкий, Sequence простіший/швидший.

## Ключові висновки / рекомендації
- Для прототипу/малого бюджету: почніть з BM25 + простого генератора.
- Для кращої семантики та масштабованості: dense retrieval (DPR) + ANN (FAISS/HNSW) + cross‑encoder reranker для топ‑N.
- Якщо важлива актуальність/оновлюваність: RAG дозволяє оновлювати базу знань без перетренування генератора.
- Якщо цінна прозорість: забезпечте повернення джерел і використовуєте reranker для скорочення «галюцинацій».
