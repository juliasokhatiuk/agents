# RAG і підходи до retrieval

## Огляд
Retrieval‑Augmented Generation (RAG) — підхід, який поєднує інформаційний пошук з генеративними мовними моделями (LLM). Під час відповіді модель спершу дістає релевантні документи з зовнішньої бази знань (корпус, векторна БД, індекс) і використовує їх як контекст при генерації відповіді. Це дозволяє LLM працювати з актуальною та домен‑специфічною інформацією без повного донавчання моделі.

## Ключова інформація — типовий RAG pipeline
1. Індексація: документи/дати перетворюються у форму, зручну для пошуку (інвертований індекс для sparse, ембеддінги для dense, або комбінований індекс).
2. Retriever: за запитом вибираються top‑k релевантних одиниць (документів/пассажів).
3. (Опційно) Reranker: перенадає отриманий набір більш точним, зазвичай повноцінним cross‑encoder-ом.
4. Augmentation: вибраний контекст додається до prompt‑а ("prompt stuffing").
5. Generator: LLM генерує відповідь на основі запиту + підставлених документів.

Переваги: зниження галюцинацій, оперативне оновлення знань, можливість прозорих посилань на джерела.

## Підходи до retrieval (детально)
1. Sparse retrieval (класичний IR)
   - Приклади: BM25, TF–IDF.
   - Як працює: інвертований індекс, пошук за ключовими словами/термами.
   - Плюси: дуже швидко, добре працює при точних ключах, легко інкрементувати/оновлювати.
   - Мінуси: чутливий до лексичної різниці між запитом і документом (синтаксичні/семантичні варіанти можуть пропуститися).

2. Dense retrieval (векторний)
   - Приклади: DPR (Dense Passage Retrieval), dual‑encoder, Sentence‑Transformers.
   - Як працює: документ і запит кодуються в ембеддінги; пошук — найближчі вектори (ANN: FAISS, HNSW, Annoy).
   - Плюси: краще захоплює семантичну релевантність, стійкіший до перефразувань.
   - Мінуси: індексація/пошук дорожчі, важче інкрементувати й контроль косинусної відстані; потребує апаратного прискорення для великих корпусів.

3. Hybrid retrieval (sparse + dense)
   - Комбінується сильні сторони обох: BM25 швидко дає кандидати, dense покращує релевантність; поєднують ранжування або сумування скорів.
   - Часто дає кращу практичну якість без значного падіння швидкості.

4. Reranking (cross‑encoder)
   - Cross‑encoder оцінює запит + документ разом (часто за допомогою Transformer) і дає точний скор.
   - Застосовується як другий етап після швидкого retriever‑а (тобто обробляє менше кандидатів).
   - Плюси: висока точність ранжування; Мінуси: повільніше й дорожче.

5. Generative / autoregressive retrieval
   - Ідея: модель напряму генерує ідентифікатори документів/пасажів (наприклад GENRE або seq2seq як retriever).
   - Може бути корисним для закритих ентропійних індексів (наприклад, відтворення canonical IDs) або для інтеграції з генератором.

6. Structured retrieval / KB lookup
   - Пошук по графам знань або SQL‑запити до структурованих БД; може поєднуватися з природною мовою (semantic parsing).
   - Використовується там, де важлива точність чисел або логічні відношення.

7. Мультихоповий і ланцюжковий retrieval
   - Для запитів, що потребують додаткових кроків/логіки: послідовні звернення до retriever‑а (multi‑hop) або використання chain‑of‑thought + retrieval.

8. Різні стратегії навчання retriever‑ів
   - Contrastive learning / DPR: позитивні та негативні приклади, in‑batch negatives.
   - Pretraining tasks: Inverse Cloze Task (ICT) — імітує retrieval підготовкою ембеддінгів.
   - Supervised fine‑tuning: мінімізувати розбіжність між retriever‑ом і генеруючим модулем (наприклад, оптимізація для кращого перплексіті відповіді).
   - Distillation: використовувати cross‑encoder або генератор як вчителя для навчання швидкого dual‑encoder.
   - RL / самонавчання: retriever може навчатися на підставі сигналів від генератора або людського фідбеку.

9. Додаткові трюки та методики
   - Query expansion / reformulation: переформулювання або розширення запиту (paraphrase, query‑builders).
   - Maximum Marginal Relevance (MMR): баланс релевантності й різноманітності.
   - Chunking / passage‑level indexing: індексація на рівні пасажів замість повних документів для точнішого витягання.

## Порівняння — основні trade‑offs
- Якість vs швидкість: cross‑encoder дає високу точність, але повільний; dual‑encoder швидкий, але іноді менш точний.
- Латентні вектори краще для семантики, sparse — для точних ключових термінів.
- Оновлюваність: sparse ієрархічно простіше оновлювати; dense вимагає переіндексації або стратегій інкрементального додавання.
- Інфраструктура: vector retrieval потребує ANN‑бібліотек (FAISS/HNSW) та більше пам’яті/гпу для великих корпусів.

## Практичні поради / коли що обирати
- Малий корпус, часті точні запити → BM25 / sparse.
- Великий корпус, багато перефразувань/семантичних запитів → dense (DPR) або hybrid.
- Висока критичність точності (юристи, медицина) → fast retriever + cross‑encoder reranker + джерела в відповіді.
- Потреба в оперативних оновленнях (логі файли, документи) → архітектура з легкою інкрементальною індексацією або шаром sparse для нового контенту.

## Ключові висновки
- RAG підвищує достовірність і актуальність LLM, додаючи поверх генератора механізм пошуку релевантних документів.
- Підхід до retrieval треба обирати залежно від вимог: точність, затримка, масштаб, частота оновлень.
- Часто практичні системи поєднують декілька підходів: hybrid retrieval + reranking + chunking.
